# Translating Agentic Desktop

Norwegian Bokmål (`nb`) is the source, not an English pivot language. Source text is the lookup key: retain its spelling, punctuation, and meaningful whitespace. There is no `nb.json`. Missing or empty translations fall back to the Norwegian text, not to English. See [the work plan](I18N-PLAN.md) for source-file ownership and estimates.

## Writing UI text

```tsx
import { t, plural } from "../lib/i18n";

<button aria-label={t("Åpne {name}", { name: project.name })}>{t("Åpne")}</button>
<p>{plural(files.length, "Slett {count} fil", "Slett {count} filer")}</p>
```

Translate a whole phrase so each language can reorder its words. Use named `{placeholders}`, never computed keys, concatenated translations, or interpolated template literals as keys. `plural(count, one, other, values?)` supplies `{count}` and selects the source form using the active language’s `Intl.PluralRules`; categories other than `one` use `other` (including Japanese and Chinese). Keep the placeholder names unchanged in each translated form. Pass user content as values, not keys. Do not translate IDs, commands, CSS selectors, shortcuts, or persisted values. Include tooltips, empty states, notifications, and accessible names.

`t`, `plural`, and `language()` read a Solid signal. Call them in JSX, a memo, or an accessor, **not once during module or component initialization**. For example, use `const choices = () => [{ value: "code", label: t("Kode") }]` and `<Select options={choices()} … />`. A stable option object with `get label() { return t("Kode"); }` also works, provided its consumer reads the getter reactively. Use `language()` with `Intl`/`toLocaleString`; `localizedFormat(locale => new Intl.DateTimeFormat(locale, options))` caches expensive formatters and tracks language changes when `.format()` is called.

## Settings, catalogs, and Electron

The optional `Settings.language` goes through `PATCH /api/settings`; its value is `system` or a supported language code. An absent setting means `system`. Browser startup waits for bootstrap and the selected catalog **before** rendering the app. Use Electron’s application locale when available, otherwise the browser preference list. Norwegian `nb`, `nn`, and `no` select Bokmål; match other languages by base language, then fall back to English. Settings changes update the document language and rendered text without reloading. The main Electron process keeps a copy of the preference in its window-state file for native UI before the server connects. Server settings remain authoritative. Native menus, dialogs and notifications import from `desktop/i18n.ts`; the desktop build copies the same JSON catalogs next to `main.mjs` and reads only the active one.

Catalogs are flat UTF-8 JSON objects under `web/src/locales/`, loaded on demand. For a new language, add its BCP 47 code and native name to `shared/i18n.ts`, add `<code>.json`, and test system matching, plurals, and the picker. When editing a key, remove the old entry from each catalog. For a fixed server `HttpError` message, an exact catalog entry is enough: the API client translates it when constructing `ApiError`. Such entries are optional; unknown errors and dynamic server messages stay intact. Do not insert translated strings as HTML.

## Commands

| Command | Result |
| --- | --- |
| `npm run --silent i18n:extract` | Print a sorted JSON array of keys. Parses TypeScript/TSX and follows translator imports, including aliases. Dynamic source arguments are errors. |
| `npm run i18n:check` | Report missing entries per language. Fail on invalid placeholders, stale keys, malformed catalogs, or dynamic calls. |
| `npm run i18n:check -- --strict` | Also fail on missing entries. Enable this in CI once all catalogs are complete. |

The web test harness and Electron launch helpers pin the system language to Bokmål. Keep existing Norwegian assertions. Add separate tests for other locales, including live changes and persistence, rather than weakening existing assertions.
